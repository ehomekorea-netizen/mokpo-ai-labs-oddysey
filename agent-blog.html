Chapter 1 · Paradigm Shift

말만 하는 AI vs 진짜 일하는 AI

챗봇은 글을 써줄 뿐이지만, 에이전트는 현실의 웹사이트에 들어가 일을 끝냅니다.
대화형 챗봇 (ChatGPT 등) 💬 텍스트 응답
  • 결과물: 채팅창 속 텍스트 답변
  • 실행: 사람이 일일이 복사해서 블로그에 붙여넣어야 함
  • 한계: 외부 사이트 로그인이나 버튼 클릭 불가
  • 시간: 내가 화면을 보고 프롬프트를 칠 때만 동작
AI 에이전트 (피클 등) ⚡ 실제 작업 완수
  • 결과물: 블로그 임시저장 완료, 예약 확정, 전화 통화
  • 실행: AI가 직접 크로미움 브라우저를 열고 조작
  • 도구: 가상 컴퓨터, DOM 제어, 파일시스템, 볼트 금고
  • 시간: 내 폰이 꺼져도 24시간 클라우드에서 자율 수행
Chapter 1 · Architecture

내 폰과 완전히 분리된 클라우드 샌드박스

내 스마트폰 화면을 가로채거나 배터리를 닳게 하지 않습니다.
🖥️ 가상 브라우저

서버 내부의 격리된 크로미움 엔진. 내 폰 브라우저의 쿠키나 개인 기록을 침범하지 않고 안전하게 독립 세션으로 작동합니다.

🔐 볼트 금고 (Vault)

아이디와 비밀번호, 결제 카드는 엔클레이브에 암호화 보관. AI 모델조차 비밀번호 평문을 보지 못하며 웹 폼에 자동 주입됩니다.

📂 파일 & 스케줄러

원고 파일 임시 백업, 구글 드라이브 연동, 정해진 시간이나 상태 변화를 감시하는 백그라운드 루틴이 24시간 돌아갑니다.

Chapter 2 · Core Tech

한 줄 프롬프트 뒤의 진실:
'에이전트 하네스(Harness)'란?

"드라이브 사진으로 블로그 써서 임시저장해줘"라는 단 한 줄이 실행되기 위해 어떤 소프트웨어 인프라가 받쳐주고 있을까요?

Chapter 2 · Concept

두뇌(LLM)에 손과 발을 달아주는 하네스 환경

에이전트 스터디의 본질은 프롬프트 말장난이 아닌 '도구와 제어 인프라'의 이해입니다.
🧠 LLM 모델 단독 (Brain)

입력된 텍스트 다음 단어를 확률적으로 예측하는 텍스트 연산기일 뿐입니다.

  • 브라우저를 띄울 수 없음
  • 파일을 저장하거나 읽을 수 없음
  • 버튼을 클릭하거나 마우스를 움직일 수 없음
🦾 에이전트 하네스 (Harness Engine)

두뇌가 세상을 감각하고 물리적 행동을 하도록 감싸는 소프트웨어 프레임워크입니다.

  • 도구함(Tools): 브라우저 클릭/타이핑, 드라이브 API, 볼트
  • 샌드박스: 안전한 파일 시스템 및 네트워크 격리망
  • 루프 제어: 목표가 달성될 때까지 상태를 피드백하는 엔진
Chapter 2 · Loop Architecture

에이전트의 심장: 자율 추론 루프

도구 호출보다 중요한 것은 '검증된 산출물'과 'Break 조건'입니다.
STEP 1
Observe (관찰)
브라우저 DOM 트리, 현재 URL, 열린 팝업 상태를 스냅샷으로 읽음
STEP 2
Plan (추론)
목표를 위해 다음에 실행할 도구(예: 스마트에디터 제목 클릭)를 결정
STEP 3
Act (실행)
browser_type, browser_upload, fill_secret 등 실제 브라우저 조작
STEP 4
Verify & Break
'임시저장 완료' 토스트가 떴는가? 확인되면 루프 탈출하고 사용자 보고
while True: state = browser.get_snapshot() # 1. 화면 관찰 action = agent.decide_action(state, goal="네이버 블로그 임시저장") # 2. 추론 if state.has_text("임시저장이 완료되었습니다"): # 4. Break 검증 take_screenshot() break browser.execute(action) # 3. 도구 실행
Chapter 2 · Deep Dive

왜 픽셀 좌표가 아니라 DOM 제어인가?

네이버 블로그 스마트에디터 ONE의 복잡한 서식 컴포넌트를 정밀 제어하는 원리
Computer Use (화면 좌표 조작) ❌ 네이버 봇 차단
  • 화면 전체 캡처를 보고 마우스 (x, y) 픽셀 좌표를 클릭
  • 창 크기, 반응형 레이아웃 변경 시 엉뚱한 곳을 클릭함
  • 기계적 직선 마우스 궤적과 비정상 입력으로 캡차/차단 유발
  • 구형 데스크톱 프로그램용 임시방편 기술
Browser Use (DOM 시맨틱 조작) ✅ 실제 사람처럼 통과
  • 실제 크로미움 브라우저 내부의 요소(ref)를 직접 타격
  • 사람과 같은 자연스러운 키스트로크 딜레이 에뮬레이션
  • 사전 인증된 쿠키/세션 재사용으로 2차 인증 피로 최소화
  • 제목 서식, 구분선 컴포넌트, 이미지 파일 첨부를 완벽 지원
Chapter 2 · Safety Boundary

사람과 AI의 안전한 책임 분계선

비밀번호는 AI가 보지 못하게, 최종 발행은 사람이 직접 누르게 설계합니다.
🔒 금고(Vault)의 비밀번호 주입
  • 네이버 비밀번호는 AI 모델에 텍스트로 전달되지 않습니다.
  • `browser_fill_secret` 명령을 통해 브라우저 입력창으로 비밀번호가 직접 마스킹 주입됩니다.
  • 대화 기록이나 로그 어디에도 내 비밀번호가 남지 않습니다.
🛑 발행 전 최종 승인 (Human-in-the-Loop)
  • 에이전트에게 맡기는 범위는 [임시저장]까지로 한정합니다.
  • 공개 글 발행은 내 이름과 브랜드가 걸리는 일이므로 에이전트가 단독으로 [발행]을 누르지 못하게 제약합니다.
  • 사람이 폰에서 확인하고 [발행]만 원클릭으로 누르면 끝납니다.

매장에서 과일 사진을 찍으면 구글 드라이브 '블로그_사진' 폴더로 백그라운드 자동 동기화됩니다.

🔍 고화질 원본 & 메타데이터

채팅방 압축 손실 없이 고화질 원본 파일과 촬영 일시, 폴더명을 에이전트가 API로 바로 읽어 들입니다.

🔄 팀 협업 & 자율 처리

팀원이 드라이브에 사진을 넣어두기만 해도 에이전트가 이를 감지하고 블로그 초안을 미리 만들어둡니다.

Chapter 3 · Pipeline Architecture

오늘 실제로 수행된 5단계 자동화 여정

목포 달디당 과일 협찬 사진 2장이 스마트에디터에 안착하기까지
01. 감지
Drive 사진 수집
드라이브 폴더에서 귤 박스, 단감, 디저트 사진 2장 파일 확보
02. 리서치
매장 검색 & 원고
카카오맵 '달디당 대성점' 주소 확인 후 마크다운 원고 백업
03. 로그인
Vault 네이버 접속
원격 브라우저 가동 및 볼트 비밀번호 주입으로 로그인 통과
04. 에디터
사진배치 & 서식
스마트에디터 ONE 진입, 제목/본문 입력, 사진 1·2 업로드, 대표썸네일 지정
05. 검증
임시저장 & 보고
[저장] 클릭, 토스트 검증, 스크린샷 캡처 후 사람에게 카드 보고!
Chapter 3 · Self-Healing

에러가 나도 멈추지 않는 '자율 회복'

단순 매크로는 에러가 나면 뻗지만, 에이전트는 대안을 찾아 스스로 해결합니다.
⚠️ 실제 발생한 돌발상황
  • 고해상도 사진 원본(1.0MB) 업로드 시 네이버에서 "일시적 파일전송 오류" 반환
  • 일반적인 자동화 매크로라면 여기서 에러를 뿜고 멈췄을 상황
💡 에이전트의 자율 문제 해결
  • 에러 메시지를 읽고 파일 크기 최적화가 필요하다고 스스로 판단
  • 내부 리사이징 도구로 1400px 웹 최적화본(250KB)을 즉시 생성
  • 재업로드 성공 후 정상 렌더링 확인하고 임시저장 완수!

Chapter 5 · Future Skills

단순 노동자에서 '지휘자'로의 전환

에이전트가 궂은일을 맡을 때, 사람은 판단과 방향에 집중합니다.
🎯 1. 골 선언 (Goal)

무엇을 왜 이루어야 하는지 의도를 명확히 제시합니다. "어떤 독자에게 어떤 가치를 전할 것인가?"

🛠️ 2. 하네스 설계 (Harness)

에이전트가 막힘없이 달릴 수 있도록 드라이브, 볼트, 브라우저의 데이터 파이프라인을 뚫어줍니다.

⚖️ 3. 가치 판단 (Judgment)

만들어진 산출물을 인간의 안목으로 검토하고, 발행할 가치가 있는지 최종 승인하고 책임집니다.
